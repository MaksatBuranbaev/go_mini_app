# Сквозные прогоны

Юнит-тесты живут в пакетах (`pnpm -r test`) и проверяют чистые функции. Здесь
лежит то, что чистыми функциями не проверяется: протокол живой комнаты и
приложение в настоящем браузере.

Доска — канва, и половина её ошибок (промах по пересечению, замерший кадр,
раскладка, разъехавшаяся между двумя тапами) в jsdom не воспроизводится вовсе.
Поэтому браузерные прогоны идут через Chrome DevTools Protocol: настоящий ввод,
настоящие пиксели, сравнение доски у двух игроков попиксельно.

## Что нужно поднять

```bash
corepack pnpm --filter @go/room dev     # комната на 127.0.0.1:8787
corepack pnpm --filter @go/web dev      # статика на localhost:5173
```

Для браузерных прогонов — headless-браузер с открытым отладочным портом:

```bash
"C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" \
  --headless=new --remote-debugging-port=9222 \
  --user-data-dir=/tmp/go-e2e --window-size=420,760 about:blank
```

Адреса переопределяются переменными `ROOM_HTTP`, `ROOM_WS`, `WEB_URL`,
`CDP_URL`, `DEV_BOT_TOKEN` — см. `lib/config.mjs`.

Комната проверяет подпись `initData` всерьёз и в dev тоже: обхода для тестов в
ней намеренно нет, поэтому прогоны подписывают данные тем же токеном, что лежит
в `apps/room/.dev.vars`.

## Прогоны

| Файл | Что держит |
|---|---|
| `protocol.mjs` | Идемпотентность `seq`, реконнект по `lastSeq`, мусорные кадры, чужая подпись |
| `endgame.mjs` | Два паса, разметка мёртвых, согласование, «доиграть», сдача, просрочка по будильнику |
| `rules.mjs` | Китайский и японский счёт на одной позиции, проверка коми, старые комнаты без поля правил |
| `sgf.mjs` | Выгрузка записи из комнаты, права на неё, уведомление ботом |
| `watch.mjs` | Наблюдатели: что видят, что им запрещено, гонка за второе место |
| `hibernate.mjs` | Выгрузка комнаты из памяти посреди партии (см. ниже) |
| `finish.mjs` | Партия до конца двумя браузерами: часы, пасы, подсчёт, результат |
| `sync.mjs` | Синхронизация двух игроков, ход при мёртвом сокете, реконнект |
| `skew.mjs` | Часы при кривом системном времени устройства и возврате из фона |
| `archive.mjs` | Архив и просмотр партии по ходам, включая доигранную после «доиграть» |
| `watch-ui.mjs` | Экран наблюдателя, полоса разрыва, экран «нет связи», ошибка в лобби |
| `polish.mjs` | Анимация захвата и звук |
| `lobby.mjs` | Правила, коми, пресеты времени и то, что выбор доезжает до комнаты |

```bash
node tests/protocol.mjs        # любой отдельно
bash tests/run-all.sh          # всё подряд
bash tests/hibernate-run.sh    # отдельно: убивает и поднимает воркер
```

Прогон на выгрузку вынесен из общего списка, потому что убивает процесс
воркера: партия играется, воркер перезапускается, партия обязана продолжиться
из `storage`. Именно этот сценарий ловит ошибки, которые прячет кэш объекта в
памяти.

Скриншоты прогоны кладут рядом с собой в рабочую директорию — это отладочный
след, а не эталон: сравнения с образцами нет, доски сверяются между собой.
