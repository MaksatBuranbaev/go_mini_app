# Звук камня

Приложение стучит настоящей записью, а не синтезом: `apps/web/src/assets/stones.wav` —
пять ударов камня о доску, уложенных в один файл по 130 мс на удар. Браузер
декодирует его один раз, а каждый ход берёт случайную ячейку — иначе серия
ходов звучит метрономом.

## Откуда взято

| | |
|---|---|
| Запись | [baduk2](https://freesound.org/s/840425/), автор Hongsungbock, 24 с |
| Лицензия | **CC0** (общественное достояние) — можно класть в репозиторий и использовать как угодно |
| Исходник | `840425__hongsungbock__baduk2.mp3` рядом с этим файлом |

Лицензия здесь не формальность: любой звук, попадающий в репозиторий, должен
разрешать это явно. CC0 — единственный вариант, который не тянет за собой
требований к атрибуции в самом приложении.

## Как пересобрать

```bash
node tools/sound/slice.mjs            # что нашлось в записи: время, пик, фон
node tools/sound/slice.mjs 0,3,6,9,12 # собрать спрайт из выбранных ударов
```

Декодирует mp3 сам браузер — тот же headless Edge, что поднят для сквозных
прогонов (см. `tests/README.md`); ffmpeg и питоновские аудиобиблиотеки не
нужны. Node только считает WAV из готовых отсчётов.

Длина ячейки задана в `slice.mjs` (`SLOT_MS`) и продублирована в
`apps/web/src/telegram/sound.ts` (`SLOT`) — при изменении править оба места.

WAV, а не mp3, потому что кодировщика в окружении нет, а 56 КиБ укладываются
в бюджет на звук и жмутся при раздаче. Если понадобится меньше — сокращать
число ударов, а не частоту: в стуке камня всё интересное выше 10 кГц.
