# Го в Telegram

Мини-приложение для игры в го вдвоём с другом. Один создаёт лобби, настраивает
партию и отправляет ссылку; второй открывает её в Telegram и садится за доску.
Ни аккаунтов, ни рейтинга, ни поиска соперника — только партия с тем, кого
позвали.

Живая версия: **[t.me/ten_gen_bot/go_game](https://t.me/ten_gen_bot/go_game)**

## Что умеет

- доски 9×9 / 13×13 / 19×19, фора, коми, выбор цвета;
- полные правила: захваты, запрет самоубийства, позиционный суперко, пас, сдача;
- завершение партии: два паса → отметка мёртвых камней → подсчёт; счёт китайский
  и японский на выбор;
- живая партия по WebSocket, часы Фишера и бёёми; просрочка времени фиксируется,
  даже когда оба игрока закрыли приложение;
- отмена хода по согласию соперника;
- наблюдатели: пришедший по ссылке, когда мест за доской нет, видит партию
  в реальном времени;
- игра на одном устройстве;
- архив партий в `CloudStorage` Telegram и экспорт SGF;
- уведомление ботом «ваш ход», если соперник отключился.

Вне рамок: матчмейкинг, рейтинг, ИИ-оппонент, турниры, анализ партий, чат.

## Архитектура

Постоянного сервера в проекте нет. Есть статика и **одна комната на партию** —
Cloudflare Durable Object, к которому оба клиента подключены по WebSocket.

```
Telegram WebView                Cloudflare
┌────────────────┐             ┌──────────────────────────────┐
│  apps/web      │  HTTPS      │  Pages (статика)             │
│  React+Canvas  │◄───────────►│                              │
│  go-engine     │             ├──────────────────────────────┤
│  (предсказание │  WebSocket  │  Worker → Durable Object     │
│   хода)        │◄───────────►│  комната = партия            │
└────────────────┘             │  go-engine (тот же пакет)    │
                               │  storage: ходы, часы         │
                               │  alarm(): просрочка времени  │
                               └──────────────────────────────┘
```

Почему так:

- **Durable Object — правильная единица.** Одна партия = один объект со своим
  состоянием и своим адресом: соперники по определению попадают в один и тот же
  объект, поэтому ни БД, ни pub/sub не нужны. Запросы к объекту сериализованы,
  так что «оба открыли ссылку одновременно» разрешается само собой — место
  достаётся первому, второй становится наблюдателем.
- **Судья — комната, движок общий.** `packages/go-engine` написан на TypeScript
  и работает и в браузере (ход отрисовывается оптимистично), и в
  Workers-рантайме (ход валидируется). Модифицированный клиент ничего не
  выигрывает.
- **Гибернация решает главную проблему го.** Игрок думает над ходом минутами,
  приложение уходит в фон. WebSocket Hibernation API держит соединение, пока
  объект выгружен из памяти. Плата за это одна, и она определяет весь дизайн
  комнаты: состояние живёт в `storage`, а не в полях класса.
- **`storage.setAlarm()` — таймкипер.** Просрочка срабатывает по будильнику на
  дедлайн текущего хода, даже если оба клиента отключены.
- **`initData` проверяется только в комнате**, HMAC-подписью с `BOT_TOKEN`.
  Токен — секрет Worker'а, в бандл он не попадает никогда; обхода проверки для
  тестов в комнате нет.

Проект целится в бесплатный план Workers: периодической синхронизации часов
нет намеренно, поэтому счётчик запросов не тикает, пока никто не ходит.

## Структура

```
apps/
  web/            # мини-апп: React + Canvas → Cloudflare Pages
  room/           # Worker + Durable Object → Cloudflare Workers
packages/
  go-engine/      # правила го: позиция, ходы, ко, подсчёт, SGF
  protocol/       # zod-схемы WS-сообщений, общие типы
tests/            # сквозные прогоны: протокол комнаты и браузер через CDP
tools/sound/      # сборка спрайта со стуком камня
```

## Запуск

Нужны Node ≥ 22 и pnpm (через corepack).

```bash
corepack pnpm install
cp apps/room/.dev.vars.example apps/room/.dev.vars

corepack pnpm --filter @go/room dev   # комната на 127.0.0.1:8787
corepack pnpm --filter @go/web dev    # приложение на localhost:5173
```

В dev-сборке окружение Telegram подменяется моком, поэтому приложение
открывается в обычном браузере. Параметры: `?dev_user=` — кто вы, `?startapp=` —
приглашение в комнату, `?dev_theme=dark` — палитра мобильного Telegram в тёмной
теме. Мок подписывает `initData` тем же фальшивым токеном, что лежит
в `.dev.vars`, — комната проверяет подпись всерьёз и в dev тоже.

Чтобы открыть приложение из настоящего Telegram, нужен HTTPS: dev-сервер
рассчитан на туннель (`cloudflared tunnel --url http://localhost:5173`), а адрес
комнаты подставляется переменной `VITE_ROOM_URL`.

## Тесты

```bash
corepack pnpm -r test        # юнит-тесты пакетов
corepack pnpm -r typecheck
bash tests/run-all.sh        # сквозные прогоны, см. tests/README.md
```

Юнит-тесты проверяют чистые функции: правила, подсчёт, SGF, часы, геометрию
доски. Всё остальное — живой протокол комнаты и приложение в настоящем
браузере — проверяется прогонами из [tests/](tests/): доска это канва, и половина
её ошибок в jsdom не воспроизводится вовсе. Отдельный прогон убивает процесс
воркера посреди партии и требует, чтобы партия продолжилась из `storage`.

## Свой экземпляр

1. **Бот.** В BotFather: `/newbot`, затем Bot Settings → Configure Mini App
   с адресом будущей статики; там же кнопка меню в чате. Команд у бота нет —
   вебхука в проекте тоже нет, отвечать на них некому.
2. **Комната.** В [apps/room/wrangler.jsonc](apps/room/wrangler.jsonc) поправьте
   `ALLOWED_ORIGINS` (откуда пускать) и `MINIAPP_LINK` (куда ведёт кнопка
   в уведомлении), затем:

   ```bash
   corepack pnpm --filter @go/room exec wrangler secret put BOT_TOKEN
   corepack pnpm --filter @go/room run deploy
   ```

3. **Статика.** Адрес комнаты и ссылка на мини-апп задаются переменными сборки —
   скопируйте [apps/web/.env.example](apps/web/.env.example) в
   `apps/web/.env.local` и подставьте свои. Сборка идёт на своей машине, а в
   Pages уезжает готовый `dist`, поэтому переменные нужны здесь, а не
   в настройках проекта Pages (те работают, только если Pages собирает сам
   из git). Без `VITE_ROOM_URL` приложение падает на старте с внятной ошибкой,
   а не стучится в никуда.

   ```bash
   corepack pnpm --filter @go/web run build
   corepack pnpm --filter @go/web run deploy
   ```

`run` перед именем скрипта обязателен: у pnpm есть своя команда `deploy`,
и без `run` запустится она.
